# AuthCheck Server

الخادم الخلفي اللي يربط تطبيق AuthCheck بذكاء اصطناعي حقيقي (Anthropic API) لتحليل صور المنتجات.

## التشغيل المحلي

1. احصل على مفتاح API من: https://console.anthropic.com/settings/keys
   (يحتاج حساب Anthropic فيه رصيد — التسعير حسب الاستخدام)

2. انسخ ملف البيئة وضع مفتاحك فيه:
   ```
   cp .env.example .env
   ```
   ثم افتح `.env` وضع مفتاحك مكان `sk-ant-your-key-here`

3. ثبّت الحزم وشغّل الخادم:
   ```
   npm install
   npm run dev
   ```
   بيطلع لك: `AuthCheck server running on http://localhost:3000`

## توصيل التطبيق بالخادم

بما إن تختبر على جوال حقيقي عبر Expo Go، الجوال ما يقدر يوصل لـ `localhost` (لأنه يقصد الجوال نفسه، مو جهاز الكمبيوتر). بدلها:

1. اعرف IP جهاز الكمبيوتر على نفس الشبكة (Wi-Fi):
   - Mac/Linux: `ifconfig | grep inet`
   - Windows: `ipconfig`
   - يكون شكله شيء مثل `192.168.1.23`

2. افتح `authcheck-app/src/services/analyzeProduct.ts` وغيّر:
   ```ts
   const API_BASE_URL = 'http://192.168.1.23:3000'; // ضع IP جهازك هنا
   ```

3. تأكد إن الجوال والكمبيوتر على نفس شبكة الواي فاي.

## اختبار سريع بدون التطبيق (من الطرفية)

```
curl -X POST http://localhost:3000/analyze \
  -F "link=https://example.com/product/123"
```

## النشر الفعلي (Production)

الخادم المحلي (`localhost`) يشتغل بس وأنت مشغّل جهازك. لنشر حقيقي دائم:

- **Render.com** أو **Railway.app** — الأسهل للمبتدئين، رفع مجاني للمشاريع الصغيرة
- بعد النشر، بتاخذ رابط دائم (مثل `https://authcheck-api.onrender.com`) — ضعه في `API_BASE_URL` بدل IP الجهاز

⚠️ **مهم:** لا تضع مفتاح API مباشرة في كود التطبيق (frontend) أبدًا — لازم يبقى فقط في الخادم (`.env`)،
لأن أي شخص يقدر يفكّك تطبيق الجوال ويسرق المفتاح لو كان بداخله.

## قاعدة بيانات الصور المرجعية الموثقة

الخادم يحلل بثلاث طرق حسب توفر مرجع، بالأولوية التالية:

1. **مرجع محلي موثّق (الأدق):** لو رفعت أنت صورًا مرجعية تملك حق استخدامها (منتج تصوره بنفسك،
   أو صور رسمية بترخيص) عبر الـ API الإداري، يستخدمها أولًا.
2. **بحث لحظي عبر الإنترنت:** لو ما فيه مرجع محلي، ويحدد النظام الماركة من صورة العميل،
   يبحث لحظيًا (وقت الطلب فقط) عن صور مرجعية عبر Bing أو Google Custom Search API،
   يقارنها بالذاكرة فقط، **ولا يخزّنها على القرص أو بقاعدة بيانات أبدًا** — تُحذف تلقائيًا
   بعد انتهاء الطلب.
3. **تحليل عام:** لو ما توفر أي مرجع، يرجع لتحليل عام بمعرفة النموذج (أقل ثقة، ويوضح ذلك
   بحقل `usedVerifiedReferences: false`).

### تفعيل البحث اللحظي (اختياري)

هذي الميزة تحتاج اشتراك بـ API بحث صور رسمي ومرخّص (مو استخراج غير مصرّح به من المواقع):

- **Bing Image Search** (عبر Azure) — سجّل بـ Azure Portal، فعّل خدمة "Bing Search",
  وضع المفتاح بـ `BING_IMAGE_SEARCH_KEY`
- أو **Google Programmable Search Engine** — أنشئ محرك بحث مخصص بـ
  programmablesearchengine.google.com، وفعّل "Image Search"، وضع
  `GOOGLE_CSE_KEY` و `GOOGLE_CSE_CX`

بدون أي منهما، النظام يتجاوز هذي الخطوة تلقائيًا ويرجع لتحليل عام.

### ⚠️ نقطة قانونية مهمة

لست محاميًا، لكن انتبه: حتى مع الاستخدام اللحظي (بدون تخزين دائم)، صور المنتجات وشعارات
العلامات التجارية تبقى محمية بحقوق نشر وعلامة تجارية، وتخضع لشروط استخدام API البحث نفسه.
البحث اللحظي أقرب لنمط "البحث العكسي بالصور" الشائع وأقل خطورة من بناء قاعدة بيانات دائمة،
لكنه ليس إعفاءً قانونيًا كاملًا — خصوصًا لو التطبيق صار تجاريًا بأرباح فعلية. راجع محامي
ملكية فكرية قبل التوسع الجدي.

### إضافة صور مرجعية محلية (تملك حقوقها) عبر API إداري محمي

1. ولّد مفتاح إداري عشوائي وحطه بـ `.env`:
   ```
   openssl rand -hex 16
   ```
2. أضف ماركة + منتج:
   ```bash
   curl -X POST http://localhost:3000/admin/products \
     -H "x-admin-key: YOUR_ADMIN_KEY" \
     -H "Content-Type: application/json" \
     -d '{"brand": "ExampleBrand", "productName": "Classic Leather Bag", "category": "bags"}'
   ```
3. ارفع صورة مرجعية:
   ```bash
   curl -X POST http://localhost:3000/admin/reference-images \
     -H "x-admin-key: YOUR_ADMIN_KEY" \
     -F "image=@/path/to/verified-photo.jpg" \
     -F "productId=1" \
     -F "angleTag=logo-closeup" \
     -F "source=owned-photographed-by-me"
   ```

## النشر الدائم على الإنترنت (بدون تشغيل جهازك)

الخطوات التالية تحتاج حسابك الشخصي — أنا جهّزت كل الإعدادات، وأنت تنفّذها بضع دقائق:

### الخيار الموصى به: Render.com (فيه خطة مجانية)

1. أنشئ حساب مجاني على **render.com** (يمكن تسجّل مباشرة بحساب GitHub)

2. ارفع مجلد `authcheck-server` إلى مستودع GitHub خاص بك:
   ```bash
   cd authcheck-server
   git init
   git add .
   git commit -m "AuthCheck server"
   ```
   ثم أنشئ مستودع فاضي على github.com وارفعه (GitHub يوريك الأوامر بالضبط بعد إنشاء المستودع).

3. من لوحة Render: **New +** → **Blueprint** → اختر مستودع GitHub اللي رفعته.
   Render بيقرأ ملف `render.yaml` الموجود بالمشروع تلقائيًا ويجهز كل شيء.

4. Render بيطلب منك تدخل القيم السرية (اللي ما ترفع لـ GitHub لأسباب أمنية):
   - `ANTHROPIC_API_KEY` — من console.anthropic.com
   - `ADMIN_KEY` — أي نص عشوائي طويل تختاره
   - `BING_IMAGE_SEARCH_KEY` أو `GOOGLE_CSE_KEY`/`GOOGLE_CSE_CX` (اختياري)

5. اضغط **Deploy** — بعد دقيقتين تقريبًا، بتاخذ رابط دائم مثل:
   ```
   https://authcheck-server.onrender.com
   ```
   هذا الرابط يشتغل 24 ساعة، حتى لو جهازك مسكّر.

6. افتح `authcheck-app/src/services/analyzeProduct.ts` وغيّر:
   ```ts
   const API_BASE_URL = 'https://authcheck-server.onrender.com'; // رابطك من Render
   ```

⚠️ **ملاحظة عن الخطة المجانية:** بعض خطط الاستضافة المجانية "تنام" الخادم بعد فترة من عدم
الاستخدام، وأول طلب بعدها يكون أبطأ شوي (ثوانٍ) لحين ما يصحى. للاستخدام التجاري الجدي
لاحقًا، خطة مدفوعة صغيرة (عادة ٧-٢٥$/شهر) تخلي الخادم نشط دائمًا بدون تأخير.

### بدائل أخرى مشابهة
**Railway.app** و **Fly.io** يشتغلون بنفس الفكرة تقريبًا، لو حبيت تقارن.

## حدود الدقة الحالية


بدون مرجع (محلي أو لحظي)، النموذج يحلل الصورة بمنطق بصري عام فقط — رأي ثاني مفيد لكنه
أقل دقة. مع مرجع، الدقة أعلى بكثير. النظام ما زال ليس بديلاً عن تحقق رسمي من الشركة
المصنّعة للمنتجات باهظة الثمن جدًا.
